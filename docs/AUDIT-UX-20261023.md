# Audit UX & Arsitektur Menu Jurnalku
Tanggal: 23 Oktober 2026 · Metode: baca kode (static) + browser headless (Playwright, chromium) + verifikasi API demo untuk 6 role (admin, kepala, guru, bendahara, siswa, wali_murid).

## Ringkasan eksekutif
- 145 route dijelajah live; SEMUA render tanpa JS error fatal dan tanpa halaman kosong. Aplikasi sehat secara fungsional.
- Temuan terbesar BUKAN bug runtime, melainkan **utang arsitektur**: menu didefinisikan di TIGA tempat berbeda yang sudah saling menyimpang. Satu role melihat menu berbeda di sidebar desktop vs bottom-nav mobile vs sheet "Semua Menu".
- 4 masalah nyata yang mengganggu user (dead link / fitur tak terjangkau) ditemukan dan butuh perbaikan.

---

## TEMUAN KRITIS — Tiga sumber menu yang divergen

Menu didefinisikan di tiga file independen:

| Sumber | File | Dipakai oleh |
|---|---|---|
| A (kanonik) | `src/lib/menuItems.tsx` (`menuForRole`) | MobileMenuSheet "Semua Menu", filter operator/TU |
| B (lokal) | `src/components/layout/Sidebar.tsx` (hardcoded `siswaMenuItems`, `kepalaMenuItems`, `bendaharaMenuItems`) | Sidebar DESKTOP untuk siswa/wali/kepala/bendahara |
| C (lokal) | `src/components/layout/BottomNavigation.tsx` (`roleItems`) | Bottom nav MOBILE semua role |

`menuForRole()` hanya dipanggil sidebar untuk admin/operator/TU/guru/wali_kelas/proktor. Untuk **siswa, wali_murid, kepala, bendahara** sidebar memakai array LOKAL (B) yang isinya beda dari kanonik (A).

### Bukti divergensi — siswa (3 versi berbeda)
- **A (kanonik)**: Dashboard, Absensi Saya, Jadwal, Ekskul, Ujian, Perpustakaan Digital (6 item, route asli)
- **B (sidebar desktop)**: Dashboard, Rekap Kehadiran `#kehadiran`, Tagihan `#tagihan`, Top-up QRIS, Tabungan `#tabungan`, Nilai `#nilai`, Jadwal Hari Ini `#jadwal`, Tugas `#tugas`, Perpustakaan (9 item, campur hash-anchor)
- **C (bottom nav mobile)**: Home, Absensi `/siswa/absensi`, Jadwal `/siswa/jadwal`, Nilai `/siswa/nilai`, Tugas `/siswa/tugas`, Tagihan `/siswa/tagihan`, Tabungan `/siswa/tabungan`, Perpus, Posting (9 item, route asli semua)

Akibat: siswa di desktop klik "Nilai" → scroll ke section dashboard (`/siswa#nilai`); siswa di mobile klik "Nilai" → buka halaman `/siswa/nilai` terpisah. Perilaku beda di perangkat beda.

### Bukti divergensi — bendahara (3 versi berbeda)
- **A**: Dashboard `/admin`, Keuangan (Tagihan, Tabungan, Payment QRIS), Perpustakaan
- **B (sidebar)**: Dashboard Bendahara `/admin/bendahara`, Ceklok Saya, Tagihan, Tabungan, Buku Kas, Laporan Keuangan `/admin/bendahara#laporan`, Perpustakaan
- **C (bottom nav)**: Home, Ceklok, Tagihan, Tabungan, Perpus, Buku Kas, Laporan `/admin/bendahara`

Akibat: menuItems.tsx bendahara (A) TIDAK mencantumkan Buku Kas dan Laporan Keuangan, tapi sidebar (B) dan bottom nav (C) menampilkannya. Payment QRIS hilang di sidebar & bottom nav, padahal ada di kanonik.

### Dampak
Setiap tambahan fitur/menu baru harus diedit di 2–3 tempat; kalau lupa satu, menu muncul di desktop tapi hilang di mobile (atau sebaliknya). Ini akar dari bug navigasi desktop yang baru diperbaiki.

**Rekomendasi**: jadikan `menuForRole()` + `menuItems.tsx` satu-satunya sumber; hapus array lokal di Sidebar.tsx dan roleItems di BottomNavigation.tsx, ganti dengan pemanggilan `menuForRole`/`flattenMenu` yang sudah ada. (Perubahan besar — perlu siklus sendiri, bukan bagian audit ini.)

## TEMUAN TINGGI — navigasi mati / fitur tak terjangkau

### 1. Sidebar wali_murid = dead link (konfirmasi live)
Wali murid diarahkan ke `WaliDashboardPage`, tapi sidebar desktop (array lokal B) menampilkan menu siswa ber-anchor hash: `/siswa#kehadiran`, `/siswa#tagihan`, `/siswa#tabungan`, `/siswa#nilai`, `/siswa#jadwal`, `/siswa#tugas`.
`WaliDashboardPage` TIDAK punya section `id="nilai"`/`id="tagihan"`/dst dan TIDAK punya handler hash-scroll. **Klik "Nilai"/"Tagihan"/"Tabungan"/"Tugas"/"Jadwal" tidak melakukan apa pun** (hanya pindah URL ke `/siswa#nilai` tanpa scroll).
- Dibuktikan via browser: sidebar menampilkan 6 anchor, dan `document.getElementById('nilai') === null`.

### 2. Menu guru "Penugasan" (`/guru#tugas`) = dead link
`GuruDashboard` punya `<div id="tugas">` tapi TIDAK punya handler hash-scroll (`location.hash`/`scrollIntoView` tidak ada). Klik "Penugasan" di sidebar guru mengubah URL jadi `/guru#tugas` tanpa menggulir ke section. (SiswaDashboard PUNYA handler; GuruDashboard TIDAK — inkonsistensi.)

### 3. Role `wali_kelas` = fitur "Ledger Nilai" & "Kelas Wali Saya" tak terjangkau
- Menu "Ledger Nilai" dan "Kelas Wali Saya" HANYA muncul untuk role `wali_kelas` (`menuForRole`), dan route `/guru/nilai-ledger` digerbang `exactRoles=['wali_kelas']`.
- Halaman "Wali Kelas" (`WaliKelasPage`) hanya mengisi `rombel.wali_kelas_id` (referensi GTK), TIDAK mengubah role user menjadi `wali_kelas`.
- Tidak ada auto-promote: `rombel.wali_kelas_id` tidak pernah menyetel `users.role`.
- **Produksi punya 0 user ber-role `wali_kelas`** → fitur Ledger Nilai + Kelas Wali Saya praktis tidak bisa diakses siapa pun, meski guru sungguhan sudah ditetapkan sebagai wali kelas sebuah rombel.

### 4. Label role hilang di UI (kosmetik tapi kelihatan)
`ROLE_LABELS` di `src/lib/roles.ts` hanya memuat: super_admin, admin, kepala, guru, proktor, wali_kelas, siswa.
Tidak ada: `wali_murid`, `bendahara`, `operator`, `tata_usaha`, `tu`.
Akibat `roleLabel()` menampilkan string mentah `"wali_murid"`/`"bendahara"` di footer sidebar (bukan "Wali Murid"/"Bendahara").

## TEMUAN RENDAH / INFORMASI

### 5. Role didefinisikan tapi 0 user di produksi
Distribusi produksi: siswa=453, guru=52, admin=10, wali_murid=6, kepala=3, bendahara=2, super_admin=1.
Role `proktor`, `wali_kelas`, `operator`, `tata_usaha`, `tu` = **0 user**. Proktor punya route tree sendiri (`/proktor`) tapi tak ada akun demo dan 0 pengguna nyata.

### 6. Demo login tidak melayani `proktor` dan `super_admin`
`/api/auth/demo` hanya menerima: admin, kepala, guru, wali_kelas, bendahara, siswa, wali_murid. Proktor & superadmin tak bisa diaudit lewat akun demo. (Superadmin ada akun produksi; proktor tidak.)

### 7. Penamaan absensi guru membingungkan
- "Absensi Harian" → `/guru/absensi-siswa` → `GuruAbsensiSiswaQRPage` (QR scan masuk/pulang)
- "Absensi Mapel" → `/guru/absensi-mapel` → `GuruAbsensiSiswaPage` (manual per mapel)
Nama route (`absensi-siswa` = QR) terbalik dari nama komponen (`GuruAbsensiSiswaPage` = manual), dan ada redirect `/guru/absensi-harian` → `/guru/absensi-siswa`. Berfungsi, tapi penamaan tidak intuitif.

### 8. `primaryGridForRole('siswa')` = kode mati
Fungsi ini menghasilkan grid siswa ber-anchor hash, tapi `MobileMenuGrid` (pemakainya) HANYA dirender di `AdminDashboard` dan `SuperadminDashboard` — bukan dashboard siswa. Cabang siswa di fungsi itu tidak pernah dieksekusi.

### 9. 403 transient pada `/adhan.mp3`
Satu console error di admin/kepala: `Failed to load resource: 403` pada `/adhan.mp3`. Dimuat langsung return 200; kemungkinan AdzanNotifier membatalkan fetch di luar jam sholat. Minor, tapi layak dipastikan tidak spam log pengguna.

## POSITIF — yang sudah benar
- Kontrak responsive dipatuhi: Sidebar `hidden lg:flex`, bottom nav `lg:hidden`, Header `hidden lg:block`.
- Fitur gating paket (`featureAccess.ts`) konsisten antara FE dan `FEATURE_PREFIXES` server.
- Demo login terisolasi di `demo-tenant` + dijaga `DEMO_HOSTS` + `hostMilikSatuLembaga` — data demo tak bercampur lembaga nyata.
- Wali murid punya dashboard khusus (pemilih anak multi-anak) yang lebih tepat daripada dashboard siswa.
- `filterRoleItems` membatasi operator/TU dari path admin sensitif (settings, users, backup, WA gateway, tenants).

---

## Prioritas perbaikan yang disarankan
1. **Satukan sumber menu** (perbaikan arsitektur; hapus duplikasi Sidebar + BottomNavigation).
2. **Sidebar wali_murid**: tampilkan menu wali (route asli `/siswa/nilai`, `/siswa/tagihan`, dst), bukan menu siswa ber-anchor hash.
3. **`wali_kelas`**: tentukan satu jalur — entah auto-promote saat `rombel.wali_kelas_id` diisi, atau ubah gating Ledger Nilai supaya guru yang menjadi wali kelas rombel bisa akses.
4. **`#tugas` guru**: tambah handler hash-scroll di GuruDashboard (seperti SiswaDashboard) atau ubah ke route nyata.
5. **Lengkapi `ROLE_LABELS`** untuk wali_murid/bendahara/operator/tata_usaha/tu.
